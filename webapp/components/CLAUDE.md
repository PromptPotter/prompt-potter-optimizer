# webapp/components — CLAUDE.md

The rules binding what lives under `components/`. Everything that binds the whole webapp — scoring authority, data sources, the viewed address, failure handling — is [`../CLAUDE.md`](../CLAUDE.md)'s.

## Component conventions

- **Layout is three tiers, decided top-down.** Every file is exactly one of: a **primitive** (`ui/`), cross-surface **chrome** (`shell/` — anything rendering on more than one tab), or part of **one surface** (a folder each, e.g. `chat/`, `dashboard/`, `files/`, `ingest/` — the roster is this directory's listing). A file answering two is mis-filed. `components/shell/node-surface/` and `components/shell/searchpoint/` are the worked examples. **Each host owns only what its own surface can answer** — which cycle is streaming, which round is in flight, which searchpoint is being inspected — and the reading itself takes props. **IDENTITY props, never SOURCE props** — owned by [`../CLAUDE.md`](../CLAUDE.md) § Display-data sources; a host hands a shared reading *which* campaign, cycle or round and nothing more. Shared app state is a context in `lib/`, never a component; `app/page.tsx` mounts `shell/AppShell.tsx`.
- **Inside a surface, organize by domain region — one axis, never by widget kind.** `dashboard/`'s folders are the §0 primitives the operator observes (`samples/`, `scoring/`, `pipeline/` — the roster is its listing). A kind-bucket (a folder of charts, a folder of detail views) collides with that axis and rots. A domain widget no single pane owns gets its own folder (`candidates/`).
- **Never hand-roll a second modal / popover / dropdown / toggle-chip / segmented control / toolbar / clipboard copy / commit-on-blur input / brand mark.** Reach for `components/ui/*`, or add it there with an RTL test and a `*.module.css` where the thing is presentational at all. Two brand-mark switches exist and are not a duplication — `ui/VendorLogo` is who TRAINED a model, `account/providers.tsx::ProviderIcon` is who you signed IN with — but a third answering either question is. **A `VendorLogo` is a `<use>` into `VendorSprite`, which `AppShell` mounts once**: unmount it and every mark draws nothing, silently. Its geometry is generated (`scripts/build_vendor_marks.py`, gated by `--only vendor-marks`), so a mark is changed at its source, never in the table.
- **Teaching prose has ONE mechanism, and `title=` is not it** — a native tooltip is unselectable, keyboard-unreachable and dead on touch, so prose that TEACHES goes through `ui/Term` on a term or readout (it owns the dotted-underline trigger and the `tabIndex`; never re-spell that trio at a call site) and through `ui/HoverCard` wrapping a control that has nowhere else to say it. `title=` survives for exactly two jobs: repeating a string the element already shows TRUNCATED, and hinting a control that already carries its own `aria-label`. Choose by that boundary, never by string SOURCE. Teaching prose that is operator VOCABULARY rides `lib/terms.ts::TERMS` besides, so the sentence is written once for every surface saying the word.
- **Nor a second TABLE, a second measured-cell renderer, or a second detail PANEL.** Every list
  of served rows is `ui/DataTable`; every list of measured cells is a PRESET of
  `shell/measurements/MeasurementsPane` over the one served read (`GET /datasets/{name}/cells`),
  and every cell opens in `shell/cell/CellPanel` inside `ui/SidePanel`. A preset takes IDENTITY
  (which cycle, which dataset, which candidate or round) and the pane does the rest — the
  hard-samples leaderboard, a candidate's cells and a round's cells are one view grouped three
  ways, never three renderers. Grouping BUCKETS the served rows under a served key order; it
  never re-sorts them. The open cell rides the address (`x/<run>/<sample>`).
- **Nor a second pipeline GRAPH or a second LINEAGE TREE.** Every graph is `dashboard/pipeline/PipelineFlow` over the served `view` + its `tier`/`rank`; never hand-placed geometry beside it. Every cladogram is `candidates/Forest`, taking a `CladogramCtx` so a surface injects which lane is its own, what a searchpoint click means, which channels it carries and where it is CUT. **A channel's extent is the chain that PRODUCED its point**: its own course up to its own round, each course above it cut where the next hangs off, plus the seed runs that measured the anchor, whole. `extentKeys` decides it and `layout(tree, expanded, keep)` draws exactly that set; extents nest, and the narrowest one holding a node owns its ink. **Never a round-COLUMN test** — a seed is drawn one column RIGHT of the point it measures.
- **A panel that can be READ can be COPIED, and WHAT it copies is a derivation, not the host's call.** `CopyButton` goes wherever a served object is already in scope — no new fetch, no new wire type — but never inside a LABEL: it is a `<button>` (with `choices`, a `Popover` trigger whose menu still bubbles React events through its host), so a `<summary>` hosting one takes a control into its content model and accessible name. Hang it beside the label. The payload is built ONCE in `lib/derivations` (`searchpointCopyChoices`) and every host of that reading takes it: hosts differ in where the button hangs, never in what a thing IS. Offer several readings only where several are honestly distinct, and DROP the one with nothing behind it rather than copying `null`.
- **An AXIS is a value set, a permitted subset, and a start value — one `ui/ValueList` states all three.** The start value is POSITION 1 (clicking a value pulls it there, and that IS choosing it) and the ticks are the permitted set, so **the lock is DERIVED**: one permitted value is the pin, and a padlock beside it could only contradict it. 🔒 / 🔓 survives where there is no set to narrow — number, string, bool. Closed it is ONE LINE; open, the list drops OVER that line (`Popover side="over"`), so the value is on screen exactly ONCE. A value the operator TYPED wears a `user` tag, which is why `available_models` is served as the ADMIN's catalogue alone. `model` is an axis like any other; its ticks are the one permitted model set, both what the optimizer may pick and what a human fork may steer to un-tainted. **Each of the three is present exactly when its CHANNEL is** — no `onPick` and the rows are text, no `checked` and the tick column is gone, no `onToggleLock` and no padlock draws. **Gate on the FACT, never on one callback**: `onApply` carries both the value and the narrowing (`config` + `optimizer` in one patch), so testing `onNarrowing` alone strips the tick column from the check-in surface; a lone node (`isSingleNode`) loses only the whole-node lock, never a padlock or a tick. And **one axis is asked once** — `NodeConfigEditor` is the single editor for every host, `ConfigMode` picking only the value TRANSPORT (draft `pipeline_overlay` vs sparse fork seed); two transports are never two questions.
- **A row answers TWO questions, never three: who may SEARCH it (`never_axis`/`movable_by`) and what widget can EXPRESS it (`kind`).** "May the operator set it" is not one of them — a searchpoint's config is one overlay and L1, L2 and a human all write into it, which is what makes a steer the same act as a mutation. The search fence is server-side and three deep (`node_param_keys`, `l1_strict`, `build_l1_response_schema`); a browser-side gate beside it is a fourth answer to a settled question. `configRows` keeps `prompt` rows, because every emit must carry their lock, and only the grid skips drawing them: the prompt editor draws each field with its own 🔓 / 🔒 through `nodeLockPatch`, the one lock emitter for a surface outside the grid. A `nested` value gets a JSON textarea that refuses to commit what it cannot parse — never drop or fold the ROW; `compact` is a density, never a subset. **The SCHEMA is the one thing the server keeps out of the rows** (`node_config_schema` subtracts `OUTPUT_SCHEMA_KEY`) — `NodeSurface`'s own `OutputContract` renders it, never a flat JSON box in the grid. **A check-in authors one there instead** — `SchemaTreeEditor` REPLACES that reading on the host, one row per field (name, type, description) whose `+` grows a branch beneath it, and a lock per row for that field's description — one served `description` row per field path. A click locks or opens the field AND its branch (`descriptionSubtree`); a descendant unlocked afterwards holds for its own branch. The grid then does not ask those keys a second time (`keysAskedElsewhere`: not drawn, still in every emit): on a node with none, `json` sits struck and unticked, and ticking it surfaces the editor — the run refuses `json` until a schema exists. **Exactly one 🔓 / 🔒 mark draws per row, never two** — the lock BUTTON where the host can lock, the read-only BADGE where it cannot. The reasons an axis is shut are different operator remedies, so they ride the title along with the layer names (`l1`, `l2`) — never one generic phrase per row, never a bare layer name.
- **A card header is ONE row** — `Toolbar` + `ToolbarSep` + `ToolbarSpacer`, controls `flex: 0 0 auto`, because a toolbar that shrinks its buttons to fit is lying about how much room it has. Rare controls fold into `Menu` behind a `⋯`, lit while any is active; **a control driving one region belongs beside that region**, not in the header.
- **"Where is this run" is the MASTHEAD's, and no pane says it twice.** `shell/masthead/RunMasthead` is the one band carrying who the campaign is, what it runs with, and its STATE / BEST / BENCH / ROUNDS / SPEND, for every tab. A repeat below it is a second derivation that can disagree on screen. So a surface below the masthead carries only what the masthead does not: the remote strip what it ACTS on, `TopStrip` the hearts, the last query's clock and the trace link. **Its chips read `dash` for the VIEWED LEAF**, the one per-cycle source, and `CampaignSwitcher` lists the sidebar's own `buildForest`, so a campaign cannot read one way in the tree and another in the picker.
- **Two surfaces sharing no axis do not share a box.** The candidates card's geometry exists to hold the dendrogram on its bars; the lineage forest is a cladogram of *cycles* with no shared axis, so it is its own `ForestCard`.
- **What bounds a run is a CAP on screen, wherever it is armed** — ingest Start, the dashboard's run-limits control and the fork reconcile all offer the same spend caps, so a third label for them ("ceiling", "budget", "limit") reads as a third thing. Prose may say ceiling; a LABEL may not. The ACCOUNT's standing bound is the ALLOWANCE and keeps its own word, because a cap composes against it rather than replacing it. One parse rule too — `lib/run-limits.ts::parseCap`, where blank and out-of-range both DROP the key, so "no cap of mine" and "inherit the parent's" are one answer.
- **A text or numeric control commits on Enter or blur, NEVER per keystroke** — `ui/CommitInput` owns the discipline; do not re-implement the draft. It is two arms picked by `rows`, and the SIGNATURE keeps them apart: a multi-line value commits on blur alone, and it refuses `type` / `inputMode` outright. Each half-typed value is a *valid but wrong* request (`"1"` on the way to `"12"` disarms the look-ahead). On error keep the last good read on screen (`failureKind → invalid` is the operator's input, not a dead read), which is why the primitive latches what it SENT rather than comparing against the prop.
- **A lit chip wears the ink of what it put ON SCREEN**, never the ink of the thing it names. A chip lit in the series colour with no series drawn reads as data still loading. Lit state comes from the served value, never a local boolean — which would stay lit after the round consumed it.
- **A sidebar collapsed on a desktop must not become an empty list screen.** Below `--bp-md` the sidebar at full width IS the list screen and carries its own header and footer, so it needs no bar of its own and drops the view nav and the collapse chevron; above it, the same component is chrome.
- **A painted surface is a control too.** SVG `<g>` elements and tree nodes earn keyboard operability and a `role`; a `<canvas>` earns an `aria-label` naming what it plots — the rule is not SVG-only. The accessibility floor is the site repo's `BRAND.md` § Accessibility & inclusion, and it does not stop at HTML elements.
