## Display-data sources

The surfaces in this table back the dashboard. **Read from the right one, and pick one source per data class**.

| Surface | Reached by | Holds |
|---|---|---|
| `dashboard.json` | `lib/poll.tsx` → `useCycleStream()` | in-flight `current_round` + `rounds[]` completed summaries. **Sole source** for FitnessChart, TrendChart and the masthead's chip row — its ROUNDS and SPEND; its STATE, BEST (`facts.standing`, selection against origin) and BENCH are the viewed course's (`lib/lineage.tsx::useViewedCourse`) |
| `/hierarchy` | `lib/registry.tsx` → `useRegistry()` / `useEntry(address)`, one 10 s poll | the served entries — every campaign of every lifecycle with its courses (the sidebar's filter is layout over `facts.lifecycle`), each carrying its own `label`, `state`, `tags`, `stats` and `facts`. **Sole source** for every surface that lists, switches, docks or heads a run; tags are read through `lib/derivations/hierarchy.ts::hasTag` / `tagValue` |
| `/hierarchy/{address}` | `lib/lineage.tsx` | the served genealogy, `campaign → course → round → candidate → campaign` at any depth, indexed once by `lib/derivations/lineage-candidates.ts::indexLineage` |
| `/campaigns/{id}/cycles/{id}/rounds/{n}` | `lib/hooks/useRound.ts`, lazy | the round as a surface reads it (`RoundView`) — arms, verdict and scoreboard; its rows are the measurement log's — folded off the cycle's ledger, so a fork answers for the rounds it inherited; `rounds/round_NNNN.json` is its checkout, which the Files tab shows only as raw text beside this read |
| the AUDIT TWIN `/campaigns/{id}/cycles/{id}/rounds/{n}/audit` | `lib/hooks/useRoundNodes.ts`, lazy | the per-node LLM I/O, which lives ONLY here |
| `/datasets/{name}/cells` | `lib/hooks/useCells.ts` — shared through `lib/hard-samples.tsx`, or read for a narrowed preset by `usePresetCells` there | the MEASUREMENT LOG of one scope: the ranked samples, the candidates and every measured cell, the live round merged once on the server. **Sole source** for the hard-samples strip, the preview window and every list of measured cells; one answer opens off `/cells/{answer}` |
| `/campaigns/{id}/pipeline?at=` | `lib/hooks/useConnector.ts` → `ConnectorProvider`, keyed on `(campaign, cycle, at)` | the campaign's resolved pipeline — node graph, per-param `value` + `source`, `options` + `permitted`, served `reach`, the output contract RESOLVED at `at`, model capabilities. **Sole source** for every config row, model chip, lock glyph, reach ring and provenance badge. A CHECK-IN rides `StaticConnectorProvider` and the campaign LIST reads `CampaignFacts.runs_with` — each a second TRANSPORT of the same answer, never a second source to overlay, merge or diff against (`docs/specs/frontend-surface-contract.md` § Invariants, `I9`) |

The rules, none of them derivable from the surfaces themselves:

- **A "merge in-flight with historical" or "fall back to the round file when the dashboard hasn't written X yet" branch is the stitch pattern this section exists to prevent.** Where two genuinely are ONE series — the hard-samples dots — the SERVER merges them and the client still reads one source.
- **Take a WHOLE candidate row from whichever half has it, and choose the half ONCE.** Never fill one in from the other per field, which puts a bar and its whisker on two different polls.
- **One served pipeline resolution, addressed by campaign — no call site may choose its own source.** **A prop may name WHICH campaign/round to read; it may never name WHERE to read from.** Provenance is served per param (`source`), so a badge or a fold computed as a client-side diff against a dataset default is the drift — `I9` in `docs/specs/frontend-surface-contract.md` § Invariants is the invariant.
- **ONE band per CHANNEL, and no scale field.** A per-BAR scale must not come back — a band rescaled onto a bar that did not produce it goes silently undrawn. Both bands are 95%, because two whiskers drawn alike have to mean alike.
- **A bar-chart channel is declared ONCE**, in `components/candidates/series.ts`. Never a bare string literal joined back into a plugin.
- **An arm's key is its served `reading.arm.key`** — every join's: a round's `arms` and `cells`, a dashboard row, a live row, the bench pass, a step. A label only renders.
- **An individual is NOT a key — the entry's `address` is.** A supersede leaves the retired side on its course and a repair re-measures without re-minting, so two candidates can share `facts.individual`; `facts.answers_for_id` names the one an id resolves to. Key rows on `address`, and split with `splitRetired` (the `superseded` tag) into one collapsed row per branch.
- **`reading.election.selected: false` says nothing on its own** — a round that HELD reads exactly like one still scoring, so ask `reading.election.held`. `pickWinner` has no first-candidate fallback and must not grow one.
- **The SIDEBAR's campaign row reads the served `CampaignFacts.line`, and follows no successor pointer itself** — the server follows `index.json::superseded_by` (`CampaignStore.line_holder`) and serves the address of the course holding the line. <!-- probe: git grep -cE "superseded_by" -- webapp/lib/registry.tsx == 0 --> A pointer rather than a status, because a parent that had already stopped for its own reason cannot also say "rebased" without destroying its real `stop_reason`.
- **Two axes, kept apart.** NAVIGATION (`workspace::viewedPath` + `viewedCandidateId`) is written ONLY by the sidebar; INSPECTION (`SelectionContext.candidate`) by a bar click. **A bar click never navigates** — one slot for both makes the chart its own input. A selection is MINTED by `selectedCandidateOf` and nowhere else.
- **The audit twin selects on `round === current_round.round`, not on "has this round closed"**: the twin is flushed AT close, so the escalation calls that fire next land only in the live block. `useRoundNodes.ts` is the single resolver; never split that switch.

## A wire shape is GENERATED — never hand-declared

**Every response type comes from `lib/api/types.generated.ts`**, emitted by `scripts/build_ts_types.py` off the Pydantic model and held current by the gate's `ts-types` check; a hand-written interface drifts behind its model with every gate green. Every model a mounted route's `response_model` reaches is exported, so a new read adds its route and nothing to the script; regenerate, re-export it from `lib/api/types.ts`.

**The allowed escapes are narrow.** A route with no `response_model` has nothing to generate from, so its shape stays hand-written *and says so*. And a narrow alias is **derived**, never re-declared — `export type ActivityWindow = ActivityResponse["window"]` reads the closed set back off the generated interface. Re-typing the members is the thing this rule forbids.

**A closed set belongs on the server.** If you find a union declared only in TypeScript, that is the bug — the only named version of it lives here and nothing can catch a rename.

**`lib/api` is write modules plus one read module, not one file.** `errors.ts` (`mintIdempotencyKey`, `operatorMessage`; every module throws through `lib/api/client.ts::toApiError`) · `commands.ts` (the closed-set `/commands/{kind}` highway) · `ingest.ts` (the writes that CREATE what a command later addresses) · `account.ts` (per-user identity, which is why it is not a command). `reads.ts` stays whole: it is one job.

## Viewed identity — one address (CyclePath)

**"What am I looking at?" has ONE answer — `viewedPath`, and no surface may keep a second.** It is a **`CyclePath`** (`lib/ids.ts`): the chain of `(campaign, cycle)` hops from top-level root to leaf, mirroring the engine's re-entrant `.promptpotter/.inner/` sandbox. `lib/workspace.tsx` owns it as `pinnedPath` + `following`, with `viewedPath` derived. Drilling in is `drillInto(campaignId, cycleId)` (the workspace appends the hop; callers just name a run), backing out `backToOuter()`.

**Navigation POLICY has one owner and one entry — `workspace.tsx::navigate(path, opts)`.** What a move does beyond the address — resuming where a campaign was left (`resume`, the campaign list's own), returning from a workspace view, leaving the phone's list screen — is decided there, and `openView` is the one place a view switches. A surface names where to go and reads `useWorkspace()` itself; a navigation callback handed down from the shell is a second owner. What the workspace does NOT hold is the registry: the one `/hierarchy` read is `lib/registry.tsx`'s, read by the surfaces that list campaigns.

**Everything that DISPLAYS re-roots to the LEAF hop; only conversation identity stays on the ROOT.** Leaf: the dashboard stream, connector/pipeline hero, hard-samples panes, chat activity feed, and the selection axes (`SelectionProvider` keyed on `leafCycleId`). Root: ingest/compose-new-campaign and Files — so drilling in never mints a thread or moves ingest off the outer conversation. Leaf ids derive at the consumer (`pathLeaf`); `useLeafIsL4` is likewise the workspace's single answer rather than a per-surface lookup. **A command is addressed like a read: by the whole path** (`lib/api/commands.ts::cycleAddress`). Whether a verb acts on an inner run is the server's answer and its sentence (`domain/command_kinds.py::CyclePayload.inner_refusal`), so no surface re-targets a verb onto the root hop or disables one with a reason of its own.

**Deep-link carries the WHOLE address, and it lives in the HASH** — `lib/address.ts` owns the syntax (`#/c/<campaign>/<cycle>/<tab>/k/<candidate>/t/<offset>`, `#/account/<pane>`), `lib/workspace.tsx` is its sole reader and writer. The replayed MOMENT (`at`, an offset in the viewed leaf's ledger) is part of it, stamped with the path it is an offset into so it lapses when the view moves; every read OF that address takes it from `workspace.tsx::useMomentAt` — the dashboard, a round, the cycle-scope cells, and the campaign's tree, which the server cuts family-wide at that instant — and the ray never does, being the axis the moment is picked on. The hash rather than the path because the app is `output: "export"` behind `StaticFiles(html=True)`: there is no SPA fallback, so a real route would 404 on reload. Three parts, all required: the PATH; the CANDIDATE, because a FORK's parked node names nothing without it (same reason DESELECTING returns to the course whose TIMELINE it renders on, never to its own path with a null candidate); and the VIEW. Malformed → the view is left alone, never reset. The cycle's universal `cycle_` prefix is stripped there and nowhere else — `ids.ts::encodeCyclePath` is also the server's `?descend=` wire format and stays byte-exact.

## Polling shape

**One clock.** Every polled read is a `useRead` with `intervalMs`, registered on the one beat in `lib/read-cache.ts`: a watch is due on wall-clock multiples of its own interval, so two reads on one cadence cannot drift, and a hidden tab stops the beat. **One invalidation** — `invalidateReads(name?)` — is what a landed command, a phase change and a returning tab all call; a counter threaded into a hook to force a re-read is a second one. Four rules bind beside it:

- **ONE tree per campaign, fetched ONCE and ADDRESSED into — never a second genealogy read.** The server's recursion already reaches every fork and inner run, so a leaf surface addresses into it: a masked body is a strict **superset**, and a per-cycle row meets its candidate on `reading.arm`, which no course renumbers. Ask the tree.
- **The step window (`/hierarchy/{course}/@`) is the CHRONOLOGY, not a second tree.** The tree answers *what descends from what*, the step window *what happened when* — a fork's records interleave with its parent's. Server-side they share one family walk, so they cannot disagree about which cycles a campaign holds.
- **A step and an SSE frame arrive READ** — `HierarchyStep.facts.activity` is one record's line, `ProjectionEnvelope.activity` the run's current state, both from `promptpotter/domain/activity.py::ActivityFeed`. The browser translates no record, folds no stream and reads no frame's `payload`; a line that reads wrong is fixed there.
- **Exactly one live channel (`useCycleEvents`) and one history channel (the step window).** The window gets no SSE join and the tail no `since=`; either would be a redundant mechanism, and the ledger mtime bumps on every append, so the conditional poll surfaces a new event within one tick anyway.

## Failure handling — classify, don't bucket

**Every read rides `lib/hooks/useRead.ts`** — one keyed hook owning the gate, the abort, the auth idle, `reportIncident` and the tagged `idle | loading | ready | failed` a caller branches on; `intervalMs` is its polled form, and a hand-rolled `useEffect` fetch beside it is a second mechanism. **A read is NAMED by its descriptor** — one `{ id, load }` builder per endpoint in `lib/api/reads.ts`, and no fetch for that endpoint anywhere else. Every instance holding the same `id` shares one flight, one last body and one clock (`lib/read-cache.ts`), so a remount paints at once and revalidates behind it, and two call sites share a read by calling the same builder rather than by spelling a key alike.

**Every write rides `lib/hooks/useCommand.ts`**, for the same reason in the other direction: `slot.run(verb, send, then?)` owns the double-submit guard, the pending mark, `onAuthError`, `reportIncident`, the classified sentence and the `invalidateReads()` that follows a landed write. It NEVER throws, never retries, and never reports an address gone — a write's 404 is a missing capability. The caller keeps only its own: which subject, whether the control is enabled, the confirmation, the success side effect. The operator sentence is `operatorMessage(e, kind)` (`lib/api/errors.ts`): the server's own sentence wherever the envelope carries one, else one per kind — rendering `err.message` is the I2 violation, and so is a surface keeping its own sentence table per kind.

**A bare `catch` is the bug.** Every failure, read or write, is classified once at the transport seam by `failureKind(err)` (`lib/api/client.ts`) into `transient | auth | gone | denied | invalid | refused`, and callers branch on that, never on a status literal. Both seams throw one class, `ApiError`, minted by the one envelope parser `toApiError`; an error class outside it classifies as `transient` at every status. Every 4xx the server answered is a verdict, never `transient`: 401/403/404/400+422 have their own kinds and any other (409 conflict, 429 cap) is `refused`, whose remedy only the server's sentence names. `transient` is the safe default — 5xx, network and parse errors all land there — because the directions are asymmetric: mistaking transient for `gone` destroys the operator's view, the reverse costs one retry.

**A pending state is a CLAIM that a read is coming — so whatever marks the read started must be the same condition that issues it.** A claim whose fetch no-ops (e.g. waiting on a dataset name from a later read) reports "loading" forever, and `transient`/`invalid` cannot catch it: there is no failure to classify. Guard the claim and the fetch with one value, and release the mark in the effect's own CLEANUP — "on every abort path" is not enough while the release is async: cleanup runs before the next effect body, a `load`'s release a microtask after that body has already read the mark and returned.

**`useRead`'s `survive` needs something to survive ON.** It keeps the last good read under an `invalid` and hands it back as `kept`, so the caller renders the failure as the operator's own input only where `kept !== null` — with nothing kept, `invalid` is a dead read like any other, and the message must not render inside a branch the missing data has switched off (`/evidence` 400s on a selection with no scored rows). One status, two meanings: the kind alone cannot tell them apart.

**`gone` (404) is terminal and must stop the poll.** One owner acts — `workspace.tsx::reportAddressGone` unpins and resumes following — and **only the address's own authoritative read may report it**: list membership is not an existence test (`I7_failure_traceable`, `docs/specs/frontend-surface-contract.md` § Invariants).

The detector is the dashboard poll, the one read that speaks for the address: its route answers `warming_up` at 200 for a cycle with no declared wiring yet, so a 404 there means the cycle dir itself is gone. `useRead` confirms it over `GONE_CONFIRM_LIMIT` consecutive misses (a single 404 is a mint race), stops that read's clock and calls its `onGone`. Everyone else reacts locally without voting — notably `useCycleEvents`, whose `EventSource` **cannot see a status** and would auto-reconnect a 404 forever, so it subscribes only while the address is live.

**Every failure is reportable, and carries ids only.** `lib/diagnostics.ts` records each with the `error_id` the API stamps on its envelope (I7), localStorage-backed so it survives the reload the bug provokes. **Never** measurements or prompt text — the same rule `view-memory.tsx` states.

## Brand identity / "About this unit"

`lib/brand.ts` is the single source of brand identity, each field `NEXT_PUBLIC_*`-overridable for whitelabel, feeding the Web App Manifest, the schema.org JSON-LD, and the Account → "About this unit" pane. Version is server-owned (`APP_VERSION`), read live from `/api/v1/health`. **Never render a "verified" state while `BRAND.verification` says `self-declared`.**
