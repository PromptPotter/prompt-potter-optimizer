# L2 Internals

L2 fires when L1 has stalled (per `l1_patience`), reads cycle state, and writes any subset of OSP fields to steer the next round. Concept role: [`../concepts/the-loop.md § L2 in detail`](../concepts/the-loop.md).

L2 is one entry in the unified dispatch hub — same `LayerStrategy` shape as L3, same `fill_fixed` path, same `Bundle` per-call state. The hub is what stops L2 from accumulating its own renderers, its own surface object, its own escape hatches. See [`l1-generate-surface.md`](l1-generate-surface.md) for the registry it shares.

## Trigger

`Cycle.escalation` tracks per-layer counters. After every L1 round:

1. Improved best fitness → escalation counters reset.
2. Otherwise `l1_stall_count++`. When it hits `l1_patience`, L2 fires.

Trigger gate: `escalation.escalate_l2`; the decision is recorded as `DecisionKind.L2_ESCALATION_TRIGGER` so resume can replay it.

## Inputs — via the hub

L2's prompt template (`l2_context/1` in `optimizer_pipeline.json`) carries `{{plan}}`, `{{l2_directive}}`, `{{cycle_position}}`, `{{diagnostics}}`, `{{failures}}`, `{{critique}}`, `{{current_params}}`, `{{task_context}}`, `{{l1_signal_catalogue}}`, `{{l1_rendered_prompt}}`. `LayerStrategy.build_prompt_vars` calls `DispatchHub.fill_fixed(template, bundle)` to resolve all of them in one pass. No L2-only surface object exists — L2 is just one consumer of the global `SIGNALS` registry.

Two signals are L2-only: `l1_signal_catalogue` (the menu of names L2 may put in `l1_layout`) and `l1_rendered_prompt` (the L1 prompt-as-L1-will-see-it-next-round, generated by piping the current `opt_sp.l1_layout` through `fill_l1`). They're absent from `L1_POSSIBLE` so L2 cannot accidentally inject its own state into L1.

## Outputs

```json
{
  "directive": "...",
  "action": "normal_round" | "probe_round",
  "axis_targeted": "...",
  "l1_layout": {"persona": [...], "task_intent": [...], ...},
  "optimizer_params": {...},
  "task_context": {...},
  "rationale": "..."
}
```

Only `directive` is required. Missing fields leave the corresponding OSP state untouched.

`_parse_l2` (`escalation.py`) constructs a `TransitionResult`:

- `l2_brief`: directive string, written to `opt_sp.l2_brief` — the **`l2_directive` signal** reads this. One-round window: `clear_volatile()` zeroes it after any improving round, so a stale directive never bleeds forward.
- `action`: `"normal_round"` (default) or `"probe_round"`. Probe re-runs only the warned-query subset under the same OSP next round.
- `axis_targeted`: the axis the directive tests. Required prose when `action="probe_round"`; otherwise stamped on the cycle for the next probe-outcome render.
- `l1_layout`: coerced to `L1Layout`, validated against `validate_l1_layout(prior=opt_sp.l1_layout)`. HARD-failed layouts roll back to the prior; SOFT-flagged outcomes (e.g. unchanged from prior) ride along on `opt_sp.l2_output_failures`.
- `optimizer_params`, `task_context`: merged onto a `mutate()`-derived child OSP.

## How L2 steers L1

Two channels, both via OSP fields the dispatch hub reads:

| Channel | OSP field | L1 effect |
|---------|-----------|-----------|
| Directive | `l2_brief` | The `l2_directive` signal renders `BRIEF: {opt_sp.l2_brief}`. Default layout puts it in `task_intent` — front of mind for the LLM. |
| Layout | `l1_layout` | `DispatchHub.fill_l1` walks the layout and appends each named signal's rendering to its slot. Mutating the layout reshapes which signals L1 sees and where. |

L2 cannot edit L1's static template text and cannot toggle `answer_format` — those are code contracts. Anything L2 wants L1 to see must already be a registered signal (from `L1_POSSIBLE`).

## Side effects — `_apply_l2`

```python
osp.l2_brief = result.l2_brief
if result.l1_layout is not None:
    osp.l1_layout = result.l1_layout
osp.l2_output_failures = list(result.l2_output_failures)
cycle.escalation.record_l2_fired(...)
if result.axis_targeted:
    cycle.last_l2_axis = result.axis_targeted
record_decision(DecisionKind.PROBE_ROUND_COMMITMENT, ...)
if action == "probe_round":
    cycle.probe_next_round = True
```

The OSP is mutable Pydantic; writes happen in place. `l1_layout` and `l2_brief` are in `MEMORY_FIELDS`, so L3-spawned children inherit in-flight L2 edits via `copy_memory_to`.

The single decision recorded per L2 fire is `PROBE_ROUND_COMMITMENT` — outcome `True` if probe, else `False`. Layout/directive content are not separate decisions; they ride on the round file.

## Loop 4 — L2 self-healing via L3

`run_l2_output_validators` (`l2_validators.py`) runs deterministic checks on `directive` (length, repeat). Layout HARD failures from `validate_l1_layout` are appended to the same `l2_output_failures` list. When the list is non-empty after `_apply_l2`, the escalation driver force-triggers L3 to heal — L2's own thrashing is observable to L3 via the `failures` signal on its next fire.
