# application/jobs/ — run admission

Run admission — the launcher, the job registry that counts machine slots and holds the queue for them, the capacity that resolves how many there are, the spend cap, and the liveness reaper — plus the account's own reads of what admission counts (`quota.py::quota_status`, `account_activity.py::account_activity`). **There is ONE launch, and every entry point that starts a loop through a command reaches it there** — `launcher/launch.py::launch`, handed the command's stores, job registry and `Inline` and called from `commands/launching.py` alone — a Start takes its two halves apart, acking at `admit` so its record rides the draft's ledger into the cycle `Admitted.launched` mints — `jobs/` imports nothing from `commands/`: `launcher/admission.py::request_job` accepts, the request's `hold_*` preamble (`launcher/mint_and_start.py`, `launcher/checkin.py`) takes `admit_and_hold` through the irreversible half and answers a `HeldRun` (`launcher/run_job.py`). **What an entry point owns of it is DATA, never a callable**: which cycle (a `LaunchRequest` arm, built from the payload), in what shape (`RunMode`), and `Inline` where a person is watching the process — the run is then held for that process to drive, where every other launch is detached. A launch refused after its queue wait writes the refusal onto its job (`Job.refusal`), which `machine_status` serves. A launch path that reserves its own slot is the bug: the machine cannot report occupancy it was not told about. **A paid verb outside a run is admitted inside the application function itself**, so no way in can skip it: a SCORING PASS takes `launcher/admission.py::paid_pass` — the launch's own backbone with a `ScoringPass` holder and the ceiling it `declared`: a machine slot, refused `machine_busy` rather than queued since its caller waits on the answer, and a reservation (`mark_admitted`) a concurrent launch reads, released on every exit — and ONE LLM call takes `quota.py::paid_call`, slotless so a chat turn never queues behind campaigns. A pass counts against the machine, never against `max_concurrent_cycles`, which bounds campaigns. ONE check refuses a taken cycle to launches and passes alike (`_refuse_taken_cycle`: a producer attached, or a pass scoring it); a pass takes no claim, since a claim reads as an attached producer. **The jobs dir is machine-global and several processes attach to it**, so both facts a slot count rests on — who may admit, and whether a job's producer is alive — are OS file locks (`jobs/interlock.py`), never process memory; a cycle's own producer is the same primitive (`infrastructure/producer_lock.py`), which the reaper asks and no clock answers. Judge liveness any other way and a terminal verb reaps the server's live campaign, or a killed run wedges the box until a restart. **A server-launched run executes in its OWN process** (`launcher/run_job.py`): the server admits and mints, hands the admitting identity and the held ceiling over the child's stdin, and the child adopts the job — so a run shares no interpreter with the reads beside it and outlives a server restart as a terminal run does. **A queued job's launch INTENT never leaves the process that authenticated it**, which is why the queue needs no persisted identity and cannot resolve as the box operator; the price is that a restart drops the line, which the producer lock already cleans up.

**The embedded launch's exemption from a machine slot** — owned by [`../CLAUDE.md`](../CLAUDE.md) § Top-level modules; this layer admits it a share and a reservation through `launcher/admission.py::embedded_share`, never a slot.
