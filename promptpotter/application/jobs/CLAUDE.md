# application/jobs/ — run admission

- **Every slot is asked at `launcher/admission.py::request_jobs`** — a launch (`launcher/launch.py::launch`, the one ask that may queue), a head-to-head's arms (`launcher/head_to_head.py::admit_head_to_head`: all admitted or none, priced before any key) and a scoring pass — from `commands/launching.py`, a rate token debited under its gate per job returned (`quota.py::slot_rate`); `jobs/` imports nothing from `commands/`. <!-- probe: git grep -cE "promptpotter\.application\.commands" -- promptpotter/application/jobs/*.py == 0 --> A launch path reserving its own slot is the bug: the machine cannot report occupancy it was not told about.
- **An entry point hands DATA, never a callable**: a `LaunchRequest` arm, a `RunMode`, and `Inline` where a person watches the process.
- **A paid verb outside a run is admitted inside the application function**: a scoring pass through `launcher/admission.py::paid_pass` (a slot, refused `machine_busy`, never queued; stopped by its command's `cancel-command`, read off the account's log every `STOP_POLL_S` from whichever process sent it), one LLM call through `quota.py::paid_call` (slotless, its rate token taken before the call is booked); both refuse a taken cycle.
- **A server-launched run executes in its own process** (`launcher/run_job.py`) and adopts the job; `spawn_job` returns only once the child holds the job and its cycle claim. A queued job's intent never leaves the process that authenticated it, so a restart drops the queue.
