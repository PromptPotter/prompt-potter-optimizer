## Data

- **Source**: HuggingFace `michaelchenkj/JustLogic` (Chen 2025,
  *JustLogic: A Comprehensive Benchmark for Evaluating Deductive
  Reasoning in Large Language Models*, arXiv 2501.14851 / OpenReview
  PK5py0eznd / [blog](https://michaelchen.io/blog/justlogic)).
- **HF native split**: **single `train` split, 4,900 rows.** The
  canonical test set is **deliberately withheld** to prevent
  benchmark leakage — *"the test set is not openly released. However,
  it can be easily generated by running [`create_split.py`]. The
  test set is also available upon request to the authors."*
  ([GitHub README](https://github.com/michaelchen-lab/JustLogic))
- **Authors' canonical generation**: 7,000 instances total (1,000 per
  depth × 7 depths), stratified 70/15/15 per-depth at `seed=0` →
  train = 4,900 / val = 1,050 / **test = 1,050 (150/depth)**. The
  HF-published 4,900 rows ARE the canonical training fold.
- **Authors' canonical evaluation** ([`eval/get_completions.py`](https://github.com/michaelchen-lab/JustLogic/blob/main/eval/get_completions.py)):
  `samples_per_depth=50` → 350 test items, zero-shot or 3-shot CoT,
  last-word TRUE/FALSE/Uncertain parsing. Single overall accuracy
  metric (stratification baked into sampling, not the metric).
- **Properties**: Uniform 700 rows/depth across depths 1-7,
  label-balanced (~33.3% each TRUE/FALSE/Uncertain per depth),
  synthetic generation (no contamination risk). Random baseline =
  33.3%; human avg = 73%; ceiling per o1-preview = 81% (paper).

### Operator-defined cut (NOT canonical)

The authors' canonical test set is withheld, so for PromptPotter
meta-campaign use we carve our own from HF `train`, filtered to the
hardest stratum (depths 6 and 7 — the recon-measured in-band slice
at ~44% origin):

| Depth | Total (HF train) | Train (seed=42) | Test (held-out) |
|---|---|---|---|
| 6 | 700 | 200 | 500 |
| 7 | 700 | 200 | 500 |
| **Total** | **1,400** | **400** | **1,000** |

Per depth: deterministic seed=42 shuffle → first 200 = train, rest =
test. Selected via `load_justlogic(split='train')` /
`(split='test')`.

**Numbers produced under this cut are NOT directly leaderboard-comparable**
— the authors' published numbers used the withheld canonical test set
(70/15/15 seed=0 per-depth split, 50/depth sampling). For leaderboard
comparability later, regenerate via `create_split.py` or email the
authors.

## Scoring

`exact_match(predicted, ground_truth)` — reused from BBEH. After
stripping the last `**…**` bold span, the predicted label equals
the gold label (case-insensitive). Registered in
`promptpotter/application/scoring/formula/matchers.py::SCORING_FUNCTIONS`.

Ground truth is one of `TRUE` / `FALSE` / `Uncertain`; the
`prompts/default.json::answer_format` field instructs the model to
end its response with `**TRUE**` / `**FALSE**` / `**Uncertain**`
on its own line. Random baseline (mode-prediction) = 33%.

## Recon evidence — origin in band (2026-05-19)

| Slice | Effort | Origin | Latency | Verdict |
|---|---|---|---|---|
| depth ≥ 4, 25 samples | low | **52% (13/25)** | ~0.3s/sample | shallow filter; label-bias coast (mode-baseline 44%, 8pp lift) |
| **depth ≥ 6, 25 samples** | low | **44% (11/25)** | ~0.3s/sample | **in-band, wired stratum.** Hedge bias (17/25 preds = `uncertain`, mode-baseline = 40%, 4pp real lift) — 3 classes all used, no class-collapse. |

L1 attack surface: **break the hedge**. Prompt mutations that say
"commit to TRUE/FALSE when premises strictly determine the
conclusion; reserve `Uncertain` for genuine indeterminacy" target
this directly.

## Pipeline Notes

- Single `llm_only` node — prompt flows through `pipeline_params.llm_only.prompt`.
- Default target: `openai/gpt-oss-20b:nitro` via OpenRouter — same
  model+effort as the recon, `:nitro` for the fastest routing
  (per the AIME experience: 3-10s tail on most providers, dominant
  speed on `:nitro`).
- `reasoning_effort: low` — locked. Pinned to `low` for this campaign
  via `param_allowed_values`; `medium`/`high` are invalid — a proposal
  is rejected and self-healed, never executed. The hedge bias is a
  prompt problem, not a reasoning-headroom problem: at `high`, 20b
  burns 70-80s/sample and still hedges.
- Optimization target: prompt template (hedge-breaking discipline,
  three-class commitment, premise-checking scaffolding) and
  `temperature`.
- Per-depth analysis: after a round, read per-depth accuracy from
  the per-sample scoring projection. Depth-6 vs depth-7 lift gap
  is itself a signal — if d=6 lifts and d=7 stalls, the optimizer
  is finding shallow-reasoning tricks; if both lift in tandem,
  it's real reasoning improvement.

## Pinning

- `model` / `provider` are NOT in `optimizer.param_keys` for this
  dataset's pipeline — pinned to `openai/gpt-oss-20b:nitro` on
  OpenRouter. Operator commitment 2026-05-19: gpt-oss-20b is the
  meta-campaign model (leading open-source, fast, cheap). Swap via
  the `nodes.llm_only.config` overlay, never via L1 mutation.
